context switch is the process of saving the state of a currently running process and restoring the state of another process to allow it to run. This is typically done by the operating system's kernel when it needs to switch between different processes or threads.

saving the state of a process involves storing its CPU registers, program counter, stack pointer, and other relevant information in a data structure called a process control block (PCB). The PCB contains all the necessary information to resume the process later.

how context switch works:
1. The currently running process is interrupted, either by a timer interrupt or a system call.  
    how to interrupt a process:
    - A timer interrupt occurs when the operating system's scheduler decides that the current process has used up its allocated time slice and needs to yield the CPU to another process. The timer interrupt is generated by a hardware timer that periodically sends an interrupt signal to the CPU, causing it to pause the execution of the current process and transfer control to the kernel.
    - A system call can also trigger a context switch if the current process requests a service that requires the kernel to perform some work on its behalf. When a process makes a system call, it transitions from user mode to kernel mode, and the kernel may decide to switch to another process if the current one is blocked or waiting for I/O.
2. The kernel saves the state of the current process in its PCB, including the values of CPU registers, program counter, and stack pointer.
    what is a PCB:
    A Process Control Block (PCB) is a data structure used by the operating system to store information about a process. It contains all the necessary information to manage and control the execution of a process, including its state, CPU registers, memory management information, scheduling information, and other relevant data. The PCB allows the operating system to keep track of multiple processes and perform context switches between them efficiently.
    where is PCB stored:
    The Process Control Block (PCB) is typically stored in the kernel's memory space, which is protected from user-level processes. The PCB is usually allocated in a data structure called the process table, which is maintained by the operating system. Each entry in the process table corresponds to a specific process and contains its associated PCB. The process table is often implemented as an array or a linked list, allowing the kernel to efficiently manage and access the PCBs of all active processes in the system.
    how is PCB used in context switch:
    During a context switch, the operating system uses the Process Control Block (PCB) to save the state of the currently running process and restore the state of the next process to be executed. The PCB contains all the necessary information about a process, including its CPU registers, program counter, stack pointer, and other relevant data.

3. The kernel selects the next process to run from the ready queue, which is a list of processes that are ready to execute.
    who puts processes in ready queue:
    The operating system's scheduler is responsible for managing the ready queue and determining which processes are eligible to run. When a process is created or becomes ready to execute (e.g., after being unblocked from waiting for I/O), the scheduler adds it to the ready queue. The scheduler uses various scheduling algorithms and policies to decide the order in which processes are selected from the ready queue for execution, based on factors such as priority, fairness, and resource availability.

4. The kernel restores the state of the selected process from its PCB, loading the saved values of CPU registers, program counter, and stack pointer.

5. The CPU resumes execution of the selected process, starting from the point where it was previously interrupted.
